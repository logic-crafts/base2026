Base2026 API & AI Access

Public read-only files and agent-readable entry points for using Base2026 as an attributed source intelligence library.

Search the library Public dataset Apply research Roadmap Support

Base2026 is built to be useful to humans and AI agents without forcing either one to scrape the visual interface. The public site exposes a small read-only data layer with the same public boundary as the website: reviewed source records, public passages, creator/topic metadata, and source-backed intelligence only.

Private research vaults, raw captions, raw ASR, media files, credentials, logs, and unreviewed pipeline artifacts are not part of the public API surface.

Public entry points

  • Human search workspace: /workspace/
  • Dataset landing page and quickstart: /dataset
  • Agent-readable context file: /llms.txt
  • Public data dictionary: /data-dictionary.json
  • Public API index: /api-index.json
  • Static and dynamic sitemaps: /sitemap.xml and /sitemap-dynamic.xml

Live Cloudflare API

The production API is a read-only Cloudflare Worker surface backed by public D1 FTS5. It does not expose the private capture pipeline.

  • GET /api/health — Worker and public-search liveness.
  • GET /api/stats — current public corpus, evidence-route and privacy-boundary totals.
  • GET /api/evidence-brief?q=... — stable Evidence Brief V1.
  • GET /api/evidence-brief/v2?q=... — bounded attributable findings with corpus and ranking receipts.
  • POST /api/search/multi-search — Meilisearch-compatible request shape executed by D1 FTS5.

No browser key is required. All write operations, private artifacts and publication controls remain unavailable over these routes.

Original articles and maintained guides

These are separate from the source-corpus counters. A guide updates an existing topic URL; it does not create a second blog copy.

  • GET /api/blog and GET /api/blog/{slug} — editorial metadata and an approved public article.
  • GET /api/guides and GET /api/guides/{slug} — maintained task guides with content-bound public-source dependencies.
  • /blog/feed.xml — original-article RSS.
  • /sitemap-blog.xml and /sitemap-guides.xml — separate discovery feeds.

Guide reads recheck their declared public evidence. A changed or unavailable dependency holds the guide for correction; a hash proves which source snapshot was checked, not that a statement is true. Publication still requires the protected editorial route and separate review. No public API can write or approve content.

Static public data

These files are safe read-only exports for external tools, notebooks, audits, and AI workflows. The public dataset page explains the static/live layers and includes a reproducible query.

  • /static/manifest.json — release counts and public export metadata.
  • /static/documents.jsonl — public search documents and source records.
  • /static/passages.jsonl — public evidence passages linked to source records.
  • /static/insight_cards.jsonl — reviewed public source-backed insight cards.
  • /static/topic_signal_briefs.jsonl — deterministic summaries for strong topics.
  • /data-dictionary.json — field descriptions and public/private boundary notes.

AI usage

AI agents can use Base2026 as a source-backed research layer by reading /llms.txt, then using the public API index, data dictionary and JSONL files. When citing Base2026, prefer canonical source, topic, creator or comparison pages rather than copying raw rows.

Good use cases:

  • find creators who discuss a topic;
  • compare repeated tactics across creators;
  • inspect source-backed SEO/GEO/AEO claims;
  • build internal research notebooks from public records;
  • cite a canonical Base2026 source page with original creator attribution.

Not supported:

  • raw transcript harvesting;
  • creator impersonation;
  • private lead or admin data access;
  • writes, corrections, moderation or publication through public endpoints;
  • replacing the original creator channel.

Future MCP contract

The planned MCP layer should remain read-only at first:

  • search sources by query and filters;
  • get one source by item ID;
  • get one topic by topic ID;
  • list creators with filters;
  • compare creator viewpoints for one topic.

Every tool response must preserve attribution, canonical URLs, original source links, and public/private policy flags.
