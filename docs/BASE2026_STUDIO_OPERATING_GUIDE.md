# Base2026 Studio operating guide

Effective September 5, 2026. Base2026 Studio builds and distributes useful
free research tools through separate departments. HQ owns product decisions
and integration. This replaces single-chat execution while retaining the
existing product strategy, AgencyOS registry and supervisor.

Start with [Project State](project-memory/PROJECT_STATE.md),
[Active Phase](project-memory/ACTIVE_PHASE.md), [Next Action](project-memory/NEXT_ACTION.md)
and [the current handoff](project-memory/HANDOFF_2026-09-05_PRODUCT_STUDIO.md).
Dated history is evidence for its checkpoint; the newest accepted receipt
controls a change in current state.

## Departments

| Department | Responsibility | Current deliverable |
| --- | --- | --- |
| HQ | Priorities, conflicts, integration, merges and public releases | Accept verified department work and coordinate the next useful action |
| Identity Engineering | Existing Google identity and private saved research | Resolve `account_not_linked` after completed consent; preserve data |
| Product Engineering | Free tools that work without signup | Continue Page Readiness Check from the accepted HTML-input slice |
| Design & Media | Approved product design and truthful demonstrations | Polish Tools Studio and prepare a coherent demo kit |
| Editorial & Distribution | Useful examples and qualified delivery | Demonstrate the working WordPress companion |
| Directories | Relevant free submissions and outcome verification | Continue fitting targets using existing submission history |
| Chief Engineering | Ownership, current handoffs and review evidence | Prevent stale instructions and conflicting writes |

Department leads use the owner's requested ASTRA configuration. This is a
routing preference, not evidence of a model's observed execution. Routine
decisions remain with the assigned department; HQ resolves cross-department
conflicts. A bounded executor gets only the files and acceptance criteria it
needs. New conversations do not create additional schedulers.

## Sources of truth and one writer

AgencyOS is the existing operational registry for tasks, events and artifacts.
The human board and public project-memory are readable projections of accepted
evidence. Chats dispatch work and return concise receipts. Public docs contain
no internal identifiers, private paths, member data or raw operational logs.

Each packet names one writer for each file, checkout and shared resource.
Implement new work in a clean worktree from verified current `origin/main`.
Do not reuse another department's dirty checkout, inherit its whole historical
snapshot, or treat a default worktree as the deployed product. Transfer an
existing patch only with explicit file ownership and an exact handoff.

HQ is the sole owner of public releases and merges. Departments may create
scoped commits, push their reviewed branch and open a PR under their assignment.
Return a unique receipt with the base/commit, changed files, checks, observed
result, limitation and next action. An unresolved ownership conflict goes
to HQ once; independent assigned work may continue. HQ coordinates shared
registry/board updates through the designated writer. The existing Office
Supervisor now runs with Chief Engineering; it may reconcile accepted receipts
and dispatch bounded next work under its existing contract. Its move replaces
the previous target, and the redundant directory timer is paused; the directory
department remains active. No additional scheduler or operational store is added.

## Evidence required to finish

A reviewed candidate, merged source, deployed version and successful live
action are separate receipts. Directory submission, moderation, accepted link
and useful external product use are separate outcomes. Inspect an uncertain
external result before retrying it. More articles, chats or submissions alone
do not demonstrate adoption.

The accepted September 5 checkpoint has live Tools Studio/WordPress surfaces
and merged PR54 source. Google consent succeeded, but login returns
`account_not_linked`; the error-UX candidate is undeployed. Page Readiness
Check has an accepted safe HTML-input slice; its full arbitrary-URL live audit
remains unfinished. The accepted slice defines work scope, not a completed
implementation or live-release receipt. Check [the handoff](project-memory/HANDOFF_2026-09-05_PRODUCT_STUDIO.md)
before acting on any of these dated states.

Use the approved visual system. The factory scene is an illustration; any
timestamped aggregate public data stays visibly separate. Never show private
pipeline stages, invented user activity, endorsements or ranking results.

Keep public tools useful without registration; authentication adds private
saving. Preserve existing saved data, account-linking controls and source
attribution. Authenticated browser actions belong to the department holding
the lease. HQ currently holds that lease after Identity Engineering released
it for a supported-tool limitation; Identity continues CLI/source diagnostics.
Ordinary authorized login/popup handling may continue; report a
newly observed non-delegable challenge through the existing escalation route.

Use the smallest meaningful checks for the changed scope and public boundary.
HQ performs release acceptance. Cloudflare serves the deployed product while
local Codex/browser operations require an available host. Retain one existing
supervisor, and record unavailable measurements as unknown.
