# Base2026: research-to-action growth operating model

Status: product hypothesis and operating contract, September 5, 2026. This is
not a claim of product-market fit, autonomous customer acquisition or revenue.

## Product decision

Keep the working Cloudflare ingestion, public search, API/MCP and visual shell.
Do not rebuild the site simply to change strategy. The immediate product test
is a narrow job for an independent SEO practitioner: turn a practical question
into a source-attributed, testable next move and a usable work artifact.

The existing Evidence Search, Source Diversity Check and Source-backed Brief
are components of that workflow. The Brief assembles public records and bounded
excerpts; it does not automatically answer the question, establish consensus,
verify a creator's claims or prove that a recommendation will work.

The first worked example is
[a content-refresh experiment](examples/content-refresh-experiment.md): diagnose
a page's decline, hold query and date filters constant, choose comparison pages,
make a substantive change and record its outcome. Its example numbers are
explicitly synthetic. It is a worksheet, not an automated audit of a user's GSC.

## The growth loop

The first portable product is the [free SEO Experiment Planner skill](BASE2026_FREE_SKILLS.md)
for compatible coding agents. It uses the existing public MCP and local supplied
observations. Distribute a usable instruction/template pack, not a new hosted
model or a collection of empty keyword-tool pages. Additional SMM/GEO skills
need distinct tasks and examples rather than cosmetic renaming.

1. Identify a concrete audience job from real questions, search demand and
   the admitted public corpus. Separate a creator's suggestion from independently
   supported facts. Search volume alone does not justify a page.
2. Produce one usable result: a worksheet, comparison, decision card or agent
   recipe with inputs, worked output, limits, sources and a next action.
3. Deliver that result through an authorized, relevant channel. Adapt the
   example for the audience; do not count copied posts as independent demand
   tests. Reconcile an uncertain send before retrying.
4. Observe delivery, aggregate tool actions and voluntary feedback separately.
   A page in a sitemap is not indexing; indexing is not traffic; a tool event is
   not an identified person or demonstrated benefit.
5. Choose the next action at the actual constraint. Insufficient exposure calls
   for better distribution, use without a result calls for friction investigation,
   and a new real task from a participant calls for testing repeat value.
6. Persist the observation, decision, action and exact result before proceeding.

Potential reinforcing loops are shared work artifacts, maintained answers to
specific jobs, credited creator feedback, repeat API/MCP workflows and original
reproducible research. These are hypotheses. Initial qualified distribution is
still necessary; content cannot guarantee its own audience.

## A useful first result for beginners

The corpus supports an answer; it must not become another reading assignment.
The preferred interaction is **check → explain → fix → recheck**, with a short
plain-language answer before the evidence ledger. Missing analytics must not
prevent sensible first checks, but it does prevent claims about measured loss,
cause, or improvement.

Extend one working function through three interfaces where justified: a simple
website tool, a portable skill, and the existing read-only MCP. The first planned
online addition is a single-page technical-readiness check: response status,
indexing directives, canonical, title, links, and structured-data presence with
observed evidence and specific fixes. It is **not implemented or deployed by this
source release**, a Google indexing verdict, or an AI-visibility score.

Do not create new domains for untested variations. Shared code, one recognizable
brand, and task-specific pages are the initial structure; separate brands/domains
need a distinct audience and observed repeated use. Free access helps trial only
when the result is useful and people actually discover it.

## Operational authority and execution

The existing AgencyOS tasks, events and artifact references remain operational
authority. Checked-in source and release receipts remain product authority.
Cloudflare D1/R2 receipts remain intake authority. Do not make chat history, a
new CSV queue or another watchdog a competing source of truth.

One existing supervisor chooses the next bounded action. Root owns product
decisions, integration and release authority; Luna Max executors get exact
inputs, allowed files/actions, acceptance criteria and a destination receipt.
An unaffected channel continues when another has a genuine external blocker.
Account identity, private data, platform rules and channel-specific permissions
are not overridden by an evaluator result.

The private read-only evaluator inspects one AgencyOS experiment and an optional
fresh aggregate observation. It does not publish, launch jobs or write the DB.
The existing transactional reconciler records an operator's reviewed transition.
No new database, CMS, scheduler or agent hierarchy is required.

| Observed state | Next bounded action |
| --- | --- |
| Reviewed result is ready | Check authority, identity and dedupe, then deliver it once |
| External effect is uncertain | Inspect that exact destination before retry |
| Measurement missing, stale or QA-contaminated | Refresh evidence; preserve unknowns |
| Too little relevant exposure | Improve qualified distribution, not page volume |
| Search activity but no usable export | Inspect the workflow and output friction |
| Several exports | Ask whether another real task needs the result; do not infer retention |

Directional event thresholds are operator heuristics, not significance tests,
conversion rates, unique users or a reason to reject the market after 72 hours.
Exact optional context and historical data handling are documented in the
[measurement contract](BASE2026_ACTIVATION_MEASUREMENT_CONTRACT.md).

## SEO and distribution rules

Index stable, genuinely useful tasks and artifacts, not every query variation.
Improve an existing page when it already covers the job. Each new indexable page
needs an actual result, example, limitation, attribution and useful next step.
Do not refresh dates without a substantive change. Use `free` only for a usable
free function; `best`, `proven` or `confirmed` are not substitutes for evidence.
Follow Google's [people-first content guidance](https://developers.google.com/search/docs/fundamentals/creating-helpful-content).

Directory submissions, native posts and articles remain distribution options,
not the product or the primary success metric. Prioritize relevant placements
and a useful demonstration over arbitrary daily quotas. Do not fabricate users,
reviews, citations, case-study outcomes or backlink/indexing receipts.

## Viability and cost

The initial check is a small voluntary pilot with suitable practitioners and
real tasks. Look for applied results and subsequent requests, not compliments.
Five applied results and three repeat requests within a 10–15-person pilot are
working decision thresholds, not proof of a large market. Lack of exposure is
not a failed product trial.

Keep anonymous public research free. Only after repeat value appears, assess
a bounded paid pilot for maintained topic research, team artifacts or additional
API usage. Do not install a paywall or assume willingness to pay. Count included
quotas, existing subscriptions, marginal cash costs and operator time separately.
Cloudflare hosting and a ChatGPT subscription do not make total cost zero.

If substantive trials do not show repeat value, retain the useful open-source
asset and reduce production effort rather than endlessly expanding the office.

## Honest autonomy boundary

The deployed Cloudflare site and native intake can run without a laptop. Local
Codex, browser authoring and the local AgencyOS database cannot be described as
a laptop-independent strategy office. A scheduled local heartbeat is recovery,
not proof of cloud execution. A ChatGPT browser session is not a durable API.

Move only a demonstrated bounded decision/action cycle to an independent host
or supported cloud executor after verifying its access, cost and execution with
the Mac unavailable. Until then, full unattended growth remains unfinished.

## Release boundary

This contract does not itself deploy the context extension or publish the
worksheet on the website. Read the current phase and unique handoff for exact
source, production and operational states. Preserve existing design, D1 data,
mail, member-auth fail-closed behavior and private transcript/media boundaries.
